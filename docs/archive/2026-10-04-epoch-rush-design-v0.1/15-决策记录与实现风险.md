# 决策记录与实现风险

| 决策 | 原因 | 实际验证重点 |
| --- | --- | --- |
| 单战线与间接角色控制 | 保留进化推线节奏，让手机也能控制角色关键行为 | 三站位是否足够表达操作，避免英雄自动送死 |
| 六英雄，每局一个 | 满足多角色打法，控制同屏输入复杂度 | 六角色都能推基地，支援角色也有完成能力 |
| 三主动槽与一能量池 | 组合需选择时机与负载 | 控制/防御不能无限连放，低费技能仍有用途 |
| 18有限传承、6点预算 | 多路线但不无限堆乘区 | 先锋/守城/远征与4+2都有可用场景 |
| 四次固定三选一 | 成长路线可规划，不被随机卡池破坏 | 选择有实际取舍，达上限不能误导收益 |
| 固定词条遗物与定向制作 | 掉落有期待，首通也能完整收集 | 不用概率刷取成为主线通关条件 |
| 先记账再播掉落 | 触屏省点击，也能避免粒子丢失影响奖励 | 暂停、低画质和多杀不丢奖励 |
| 部件动画优先 | 生成图角色稳定性与成本可控 | 脚滑、武器关节和所有单位同样摆动 |
| Phaser共享模拟、平台壳分别适配 | 现有Windows环境与技能路线匹配 | WebView性能、音频恢复与储存不同实现 |
| iOS用Mac/Xcode路线 | 官方工具要求，本地禁止虚拟化 | 实际Mac构建和iPhone验证，不能只写计划 |

## 五个优先风险

1. **时代滚雪球。** 初值HP/攻击同乘时代，领先可能过强。用旧兵/炮塔/护盾应对窗口测试，优先调倍率、学识阈值和首击，不补隐蔽资源作弊。
2. **组合成为唯一答案。** 导电扩散、破甲爆炸或守城盾可能压过所有兵种。检查目标上限、能量与CD，统一条件加成池；必要时调收益而不删除组合体验。
3. **角色控制不够像可玩角色。** 如果三站位无实际差异，增加既有专属技能的可控瞄准与行为反馈；先验证它们，再决定是否增加手动短移动指令。
4. **素材在小屏糊成一团。** 风格图的机械细节与背景需要简化。实际高度先看剪影、武器与队伍标识；图标从32/64px检验，避免只验大图。
5. **跨端技术预算失守。** 同一逻辑可跨端不保证渲染和音频都顺畅。限制图集、并发、DPR与加载组，实体设备记录峰值；降特效不删游戏规则。

## 修改与范围管理

每次调整记录问题、受影响ID、数值前后、试玩证据与回归范围；更新contentVersion、文档和数据。若修改了核心角色控制、出生时代规则、掉落结算或平台壳，重新检查相关完整流程。原五预案v1归档不改写；当前设计版本另行归档。

文档阶段可以确定实现选择和填写初值；成品强度与爽感必须靠真实运行结果校准。尚未生成的素材、未实测的原生平台和未完成的关卡始终保持对应状态。
