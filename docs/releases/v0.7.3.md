# v0.7.3：Android 长屏铺满与安全区修复 / Full-screen mobile layout

当前 1280×720 设计尺寸使用 `canvas_items + keep`，导致 20:9、21:9 横屏出现等比留边。以 2400×1080 为例，旧模式把游戏限制在 1920×1080，左右各余 240 像素，合计浪费 20% 宽度。这是可复现的应用配置问题，与 AI 或手机性能无关。

此外，原导出配置只有沉浸模式，没有显式开启边到边显示；UI 没有系统安全区映射，Android 设置还允许切换桌面窗口模式。机型 ROM 的兼容模式、系统导航栏与挖孔可能叠加留边；这些设备因素没有 X30 实机证据，不能认定为此次实测的全部原因。

## 修复

- 等比扩展视口：改为 `canvas_items + expand`。2400×1080 下逻辑画布为 1600×720，场景利用新增横向空间，人物和字体不做非等比拉伸。16:9 保留原布局；更宽屏增加视野，4:3 增加纵向空间。
- Android 显式启用 `screen/edge_to_edge=true`，同时保留沉浸模式与横屏。
- 菜单背景、战场保持全屏；菜单按钮、战斗 HUD、指挥官托盘和弹窗使用独立 `SafeUI`。系统安全区从物理屏幕通过逆变换映射到逻辑坐标，处理屏幕缩放与窗口偏移，避免直接把物理像素当成 UI 像素。
- 安全区过小时 UI 等比缩小到完整容纳原 1280×720 布局，不裁掉操作栏。触控遮挡判断继续使用变换后的全局矩形，场景坐标转换保留。
- Android 启动、回到前台恢复沉浸全屏；Android 设置不再显示桌面“全屏显示”切换。Windows 仍可选择窗口或全屏。

## 验证范围

原生 Windows OpenGL 窗口渲染验证 1280×720、1600×720、**2400×1080**、1680×720、1280×960；覆盖五个菜单页面、战场、研究弹窗，模拟左右及底部安全区。检查视口比例、战场尺寸、操作栏与弹窗容纳、触控遮挡、施法坐标往返和物理安全区转换，均通过。导出包 **92/92** 屏幕适配检查通过，含安全区缩放后的触屏招募与指挥官操作。原有 **159/159** 交互回归通过。

这证明应用布局与输入修复；**不等同于摩托罗拉 X30 真机验收**。当前 ADB 没有连接设备，因此厂商强制兼容留边、挖孔与手势区域的实际返回值、后台恢复及横屏翻转仍需在 X30 上复测。Android APK 包配置、版本、签名、对齐和核心脚本另行核对。证据与截图见 [验收记录](../qa/v0.7.3/README.md)。

建议安装本版后，分别检查首页、战斗、研究弹窗，旋转到两个横屏方向，再后台切回；背景应延伸至屏幕边缘，按钮应避开摄像头。如果仍有窄条留边，需要以设备截图、Android 系统版本及应用全屏兼容设置确认是否是 ROM 限制；不要卸载以免删除本地存档。

版本 **0.7.3**，Android `versionCode=12`，包名和发行签名保持连续，可覆盖升级。

## English

The previous 16:9 `keep` aspect setting letterboxed wider phones. At 2400×1080, it occupied 1920×1080, leaving 240 pixels on each side. This release switches to proportional `expand`, enabling a 1600×720 logical canvas that fills the display without distorting actors or typography. Android explicitly enables edge-to-edge immersive rendering and restores fullscreen on resume.

Worlds/backgrounds fill the display; interactive UI uses a separate safe-area layer that converts physical insets through the inverse screen transform. Narrow safe areas proportionally scale the UI while preserving its complete layout. Desktop fullscreen controls remain available only on desktop. Five native window sizes, including 2400×1080, pass layout checks; 159 interaction regressions pass. These are desktop-rendered validation and package checks, **not physical Motorola X30 validation**. No Android device is currently attached.
