# Godot 0.7.0：十时代扩展与九项问题验收

日期：2026-10-07，Asia/Taipei。原生游戏名称：《纪元急袭》，沿用方向 1 的横向文明战争和像素指挥卡组。基线为 Godot 0.6.2；本轮扩展并修复既有规则，下一轮的集结、公开研发、竞技 AI 等机制仍是 [设计提案](godot-v0.7-gameplay-depth-and-fair-duels.md)。

## 可运行成品

- [Windows x64 便携包](../../godot/build/windows/Epoch-Rush-Godot-Windows.zip)：解压后运行 `Epoch-Rush-Godot.exe`，资源嵌入程序，无需安装引擎或网页服务。
- [Android 已签名发布 APK](../../godot/build/android/Epoch-Rush-Godot-release.apk)；[调试 APK](../../godot/build/android/Epoch-Rush-Godot-debug.apk)：arm64，最低 Android API 24。
- [Godot 源码与导出说明](../../godot/README.md)。[十时代演出录像](../../output/qa/ten-eras/video/ten-era-showcase.mp4) 展示真实模拟中的接敌、奇袭和随机事件；录像采用固定 60 帧录制，不作为实时帧率测量。
- 文件大小与完整 SHA-256 见 [最终包校验](../../output/qa/ten-eras/packages/package-asset-checks.json)，内容、签名和证据摘要见 [交付清单](../../output/qa/ten-eras/delivery-summary.json)。

两侧分别使用自己的金币、军令和交战经验。任一侧升级会更换地图，另一侧的时代、经验和旧兵不会被自动升级。打开时代图鉴，可选任一时代并进入双方同代的标准对战；当前仍按标准对战保存和结算，并非无奖励沙盒。

源码仓库不上传本机安装包、原始长录像与完整 QA 输出；上面的成品路径对应本机交付。GitHub 可阅读的精简验收 JSON 已整理到 [公开证据索引](../qa/v0.7.0/README.md)，菜单、实机图与 GIF 见 [中英双语总览](../../README.md)。

## 九项要求的实际结果

| 要求与检查发现 | 本版处理 | 验证依据 |
| --- | --- | --- |
| 医疗每个模拟 tick 重复恢复，多个医疗和持续盾可叠成不死前排 | 医疗按 1.5 秒脉冲处理，最多三个目标；治疗与被动盾共用持续恢复预算。战斗中每秒预算不超过最大生命 2% 与近期承伤压力 35% 两者较小值；脱战每秒最多 5%。持续盾上限 12%，全部护盾上限 20%；生命和盾条分开显示。修复小额浮点护盾吸收被整数量化丢失的问题 | 规则与技能回归覆盖多医疗、护盾/护甲、完全吸收的承伤压力与驻营恢复 |
| 五时代门槛低，经验随伤害一起放大，升级过快 | 九次进化门槛改为 260 / 420 / 650 / 990 / 1480 / 2180 / 3180 / 4580 / 6520。经验按每代约 1.45 倍增长，独立于五倍伤害；空等不生经验，奇袭与进化继续共用经验 | 多种子完整对局、独立进化、旧兵及已付费订单检查 |
| 奇袭缺乏时代载具和命中层次 | 十套时代奇袭素材，包含载具、弹体、冲击、烟尘、碎片与地面冲击波；预警、发射、命中、余波分阶段。地面平台贴地发射，二战轰炸机飞行投弹，轨道平台垂直打击；修复现代导弹车和无人载具误用空中轨迹的问题 | 十时代原生截图、双方载具位置/类型检查、连续录像与实际伤害回归 |
| 跨代火力差异不足 | 相邻时代同定位、同研究的基础攻击与生命按五倍增长；基地同尺度增长。价格/收入每代约 1.28 倍，经验约 1.45 倍。45 组相邻时代兵种配对的基础伤害、有效伤害和 DPS 检查均通过 | 420 项规则回归中的跨代矩阵；不将五倍倍率解释成固定胜率 |
| 时代内容仅五代 | 十时代、每代五兵种，共 50 兵种；20 关战役、20 种可建炮塔；招募、研究、百科及数值显示按十代工作 | 数据表数量与引用、运行图鉴和演练、包内 19 份 JSON 一致性检查 |
| 天空背景静止 | 按时代加入蝙蝠、鸟、翼龙、气球、飞机、直升机、无人机及穿梭机等剪影；运行时飞行、浮动和旋转，暂停冻结 | 纯表现层，不加入实体占位、命中、奖励或战斗随机流；原生截图与暂停测试 |
| 地图单调，时代切换缺少反馈 | 每代三张不同全景，共 30 张。任意一方升级触发换图，地图依据双方最高已完成时代；落后方追平时从该时代另外两张候选中抽取 | 全部 30 候选在成品 PCK 中实际加载和渲染；双方升级与地图序号独立检查 |
| 无随机弱奇袭 | 七类事件：陨石、恐龙坠落、落石、雷暴、坠机、无人机坠落、轨道残骸。预警 2.1 秒；每次伤害不超过目标最大生命 10%，不伤基地、不产金币或经验 | 首次 38–58 秒，其后间隔 48–82 秒，每局最多 14 次；独立随机流、暂停、快照及无基地伤害测试 |
| 主将时代形象与技能基本固定 | 六位主将各十套外观与技能变体，共 60 形态。进化更新当前主将的造型、武器、数值和专属技能名/参数；保留生命比例与技能冷却。旧兵、旧炮塔和旧订单仍是出生时代 | 60 次实际专属技能施放、120 个敌我形态渲染、在场换装与阵亡重生检查 |

奇袭预警为 1.15 秒，脉冲间隔 0.24 秒，依时代为 2–4 次脉冲；每次基础伤害 65 乘施放时代攻击倍率，冷却 34 秒。伤害、时代和落点在施放时冻结，途中进化不会免费抬高已发射攻击；目标数量有限且不直接打基地。画面中的多个弹体是演出密度，实际结算由脉冲规则控制。

主将的 60 个技能变体沿用冲锋、连射、掩护、部署炮台、裂隙和补给六个行为家族，按时代调整装备与参数；不是 60 种完全无关的技能系统。召唤炮台是带程序后坐力与闪光的静态角色。天空角色是运行时运动的剪影，未额外生成逐帧拍翼或螺旋桨图集。

本轮固定使用指定 [Sub2 图片生成 skill](C:/Users/carzy/.codex/skills/sub2-image-gen/SKILL.md) 和 `gpt-image-2.5`，没有更换模型或供应商。使用指定 CLI 的兼容适配补齐网关需要的 image-generation 工具声明。原始请求、提示词、参考图和文件哈希保留在 [生成目录](../../output/imagegen/ten-eras/)；[生产记录](../../output/imagegen/ten-eras/production-state.json) 为 135 项成功、0 失败、0 阻塞。这是制作任务数量，不是最终角色数量。

20 个既有兵种动作及四套基地沿用此前已接受的 Sub2 素材；新增 30 个兵种、60 个时代主将等素材完成审查。对身份/装备变化的 11 套完整动画重新生成，未采用的原图保留。实际使用 120 个角色定义：50 兵、60 主将形态和 10 个召唤炮台。110 个活动角色具有待机、移动、攻击、受击、死亡五行共 30 帧；炮台各一个静态帧。敌我两色合计 6620 个活动帧；包内另保留六个旧主将定义，所以总清单是 126 定义、252 图集、6980 非空帧。

锚点与碰撞体按角色身体处理，人物核心尺寸保持稳定，车辆使用下部车体；卡图由同一角色图集裁切。材质、武器、挂点和朝向同步核对，修正步枪角色移动时变成载具、持枪角色套近战、火箭角色套普通子弹和炮台串入邻行碎片等问题。[素材清单](../../output/qa/ten-eras/assets/asset-audit.json) 与 [逐图审查记录](../../output/qa/ten-eras/assets/visual-review.json) 绑定最终图集哈希。

UI 延续方案 1 的像素卡片、深蓝底和敌我色；图鉴增加十时代页签及同代演练入口。实际操作复核修正图鉴说明挤占整个面板、兵种卡被挤出屏幕的问题，并检查 50 个兵种名的可见边界。圆体中文和标题字体重新子集化，运行文字所需的 662 个汉字均有字形，字体许可随 Windows 包附带。

声音沿用并适配既有 43 类 / 129 个音效变体和九段音乐：菜单、五类战斗配乐、三段结算短曲；五类战斗配乐按十时代主题路由。本次不是新增十首独立 BGM。[声音设计](../../godot/SOUND_DESIGN.md) 和随包 CC0 来源/许可记录保留原作者信息。

线列装备、近现代军备与海湾战争识别参考来自英国国家陆军博物馆的 [步枪旅](https://www.nam.ac.uk/explore/rifle-brigade-prince-consorts-own)、[博因河战役](https://www.nam.ac.uk/explore/battle-boyne)、[海湾战争](https://www.nam.ac.uk/explore/gulf-war)。装备组合与五倍代差属于架空游戏设计，不是历史性能模拟。

八场完整对局包含三种一般策略和 M01 / M06 / M15 / M19 / M20 的合法操作样本，模拟时长 281.37–1899 秒；结果为我方胜三场、敌方胜四场、平局一场。石器开局样本的首次进化约 5.2–6.1 分钟，压制策略可能提前结束比赛；防守样本进入加时后完成结算。20 / 24 分钟提高战斗压力，30 分钟开始基地持续损耗。不能把八场样本解释成所有关卡都完成了人工难度校准或五五开平衡，也不要求每场必须经历全部十代。

[性能采样](../../output/qa/ten-eras/performance/performance.json) 使用本机 RTX 3060、1280×720、Compatibility / OpenGL 3.3：24 单位代表场景的帧间隔 p95 为 8.837 ms；60 单位合成压力场景 p95 为 14.538 ms，最大 46.896 ms 包含场景切换。后者故意重叠部署并重复真实奇袭，不是正常出兵规则；采样末分别有 13 / 36 个存活实体、10 / 26 个镜头内实体。静态内存约 67.4 / 68.7 MiB。这些是桌面采样，不代表全部 60 个单位同时在屏，也不代表 Android 性能。

成品 Windows EXE 直接启动并录制三秒菜单；完整战斗检查使用同版本 Godot 引擎加载最终 EXE 的内嵌 PCK，外置 QA 脚本只驱动操作，不用源码替换游戏内容。发行模板不支持外置 `--script`，因此不声称它执行了 QA 脚本。强制 `--quit-after` 结束时出现四个 ObjectDB / 一个 resource 的退出诊断；该直接启动样本无游戏脚本或资源加载错误，退出码为 0，退出诊断不作为运行内存无泄漏的证明。

Android 版本号 0.7.0、versionCode 9，应用 ID `studio.epochrush.pixelcommand`，target / compile SDK 36；仅 arm64。当前 ADB 无连接设备，尚无 Android 真机的帧率、触控手感、音频驱动或安装运行证明。本轮不包含 Godot 原生 iOS IPA，也未完成全部战役的人工平衡验收。Windows、Android 的应用数据各自存储。

工程、素材处理、引擎与 Android 工具链均在本机 Windows 原生运行，未调用 Docker、WSL 或虚拟化。下一轮新增玩法另按提案切片验证，保留本版已交付规则作为基线。
