## 代码如何对应设计

`src/content/` 直接读取策划 JSON，避免两套数值漂移。`src/core/` 是固定 30 Hz 的战斗、AI、成长和结算逻辑，独立于画面。`src/presentation/` 负责 Phaser 图像、拼接骨架、伤害反馈和音频。`src/ui/` 实现营地构筑、收藏、故事地图、战斗界面与档案交互。`src/services/` 处理 IndexedDB、导入校验、原子结算、原生生命周期、触感与导出分享。

Windows 使用隔离的 Electron 渲染进程和本地安全协议；Android/iOS 使用 Capacitor 原生工程，共用相同战斗代码。存档通过文件手动迁移，没有云服务。手机采用横屏界面，浏览器竖屏会自动暂停。

实际实现包含五个时代、20 种兵、10 座炮塔、六位英雄、18 专精、18 天赋、18 技能、12 遗物和15关卡。所有配置进入游戏；配置存在不等于每种搭配都已完成人工平衡测试。

- 战斗、档案、持续技能与快照：52 项自动化测试通过，涵盖退款、旧时代队列、人口、进化保留伤血、弹体穿透、盾与导电、技能强度冻结、持续火区、无重复奖励与原子提交失败恢复。
- 其中有30场、五时代×六构筑的自动对战验证，检查结束条件、资源、人口和有限数值；不是玩家胜率统计。
- 新增一项战役验证从新档开始，在合法资源和真实胜负下完成 M01–M03，再用实际结果结算解锁。共11场，3胜8负，详见 [战役战斗记录](../../output/qa/campaign-combat.json)。这说明成长闭环可运行，也提示前期难度仍需要人工校准。

## 素材与来源

112 张原始 PNG 使用指定的 sub2-image-gen / gpt-image-2.5 流程生成。本地规范化出角色、敌方变色版本、头像、兵卡、分层背景和特效；26套角色/单位拼接骨架含314张局部素材。角色没有用整张图片左右摇摆替代全部动作，行走、蓄力、释放、恢复、冲锋和死亡由局部部件驱动；细节仍保留动作复核状态。

197 个策划逻辑资源均有实际运行文件，运行清单含552项。32项原创合成音频由本地生成工具制作，技术检测无削波或静音文件。音频技术通过不代表听感已获人工批准。

[资源校验报告](../../output/qa/asset-audio-validation.json) 记录原图与运行文件 SHA-256。108 张原图有批量生成工具的元数据；最先制作的 base-A3、H01、H03、U31 四张原图未保留该批量工具的元数据，运行清单保留了来源路径、模型与来源哈希。没有补造批量生成记录。首次不合格的十张特效原图存放在 rejected 目录，之后重新生成，运行文件使用修订版本。

素材文件是否存在、来源是否可追踪、美术是否已审批是三个不同状态。运行清单中的 pending 审查标记仍保留，不能把资源校验报告当成全素材质量验收。原始图片、提示词、处理工具和完整实现都保存在项目中；源码包不包含供应商密钥或外部 skill 的配置文件。

## 对设计基线的具体补充

- S08 引火罐保留初始爆炸与四秒燃烧，另外实现持续火区；随后进入火区的敌人获得剩余时间的燃烧。单次施法最多影响六个不同伤害目标，初始爆炸仍最多四个。强度与结束时刻在施法时冻结。这落实了 S08→S09 的牵引连招。
- 指令序号与奖励序号都保留终身高水位，最近200条只是查询窗口。导入旧档、切换档案再导入，以及恢复备份均不能倒退本机已提交记录。
- 结算先保留战场，再在同一个 IndexedDB 事务中更新档案、备份、档案历史及收据，移除已结算对局。磁盘校验失败会保留原记录并提供恢复入口。
- 图片全部加载后才开放开战。画布按窗口比例调整，人物地面位置根据底部控制面板避让。
- 演练不持久化对局，不覆盖正式续战记录；退出按钮明确为结束演练。资源清单在启动/构建前从公共目录同步到代码目录，避免开发服务器直接导入公共目录的兼容警告。
