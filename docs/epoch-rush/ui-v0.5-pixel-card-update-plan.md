# Epoch Rush v0.5：像素卡片指挥甲板 UI 更新方案

> 选型：方案 1 · 像素卡片风（Pixel Command Deck）  
> 目标版本：v0.5 视觉与交互重构  
> 参考图：[01-pixel-card.png](../../output/imagegen/ui-selection/01-pixel-card.png)  
> 结构基线：[UI 方向选型结构说明](ui-direction-selection-brief.md)

## 1. 更新目标

把现有的“圆角 CSS 覆盖层”升级为一套完整的像素指挥甲板系统。玩家打开对局后，应先看到战场、两座大型基地和兵线，再看到可立即操作的招募、道具、时代与英雄控件。所有面板都要像游戏内的实体卡片和设备零件，不再像网页后台的分栏卡片。

本次更新保留现有战斗逻辑、存档协议、`data-action` 操作协议和 Phaser 战场；重做 HUD 的视觉令牌、HTML 层级、图标资产、状态表现、移动横屏布局和过渡动效。时代仍由每个 `SideState` 独立推进，任何 UI 重绘都不能把双方时代合并成一个全局值。

### 当前基线与主要问题

- `src/ui/screens-v03.ts` 已有顶部资源带、左上地图控制、底部招募/道具/时代/指挥官区域，但结构由一个很长的模板函数一次性拼出。
- `src/ui/command-theme.css` 仍保留大量 3–6px 小圆角、普通网页按钮和旧的网格规则；`src/ui/rounded-theme.css` 再用覆盖段改变颜色和圆角，选择器之间容易互相覆盖。
- `src/ui/icons.ts` 已接入 4×4 像素图集，但常用图标、状态图标和弹窗图标仍混用 SVG 兜底；锁定、冷却、受击、时代和主动道具缺少统一的像素状态语言。
- `EpochRounded`、`EpochDisplay` 和等宽数字已经本地加载，适合继续使用；不引入在线字体，避免桌面包、Android 包和离线运行出现字体漂移。
- `GameApp.paintHud()` 已负责资源、时代、队列、冷却、瞄准和按钮禁用状态；新的 UI 只改变渲染层，不把战斗状态复制到另一份容易失真的 UI 状态。

## 2. 视觉契约

### 2.1 像素卡片的材质

每个控件由四层组成：深色实体底、1–2px 像素描边、底部深色压边、内侧高光线。外轮廓保留适度圆角，但在四角加入 2–4px 的切角或像素缺口，使它看起来像卡牌和铆接设备，而不是网页圆角容器。

- 基础网格：4px；所有间距、图标内边距和阴影偏移使用 4 的倍数。
- 控件圆角：卡片 12px、按钮 12px、顶部/底部甲板 16px；像素切角使用 `clip-path` 或伪元素，不使用复杂渐变边框。
- 阴影：只使用实体底边和短距离投影，不使用大面积玻璃模糊。
- 纹理：允许极低透明度的像素噪点和扫描线；禁止纹理盖住生命条、资源数字或兵卡图像。
- 阵营：己方使用青蓝，敌方使用赭红；金色只代表 XP、时代和可执行的升级，不用作普通装饰。

### 2.2 颜色令牌

令牌集中在新的 `src/ui/pixel-tokens.css`，组件中不再直接散落十六进制颜色。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--px-field` | `#071722` | 战场 HUD 背景、最深层 |
| `--px-deck` | `#0B2532` | 顶部与底部指挥甲板 |
| `--px-card` | `#123746` | 普通按钮、兵卡、道具槽 |
| `--px-card-hi` | `#1B4D57` | 悬停、选中、按下后的表面 |
| `--px-line` | `#4E7180` | 像素描边和分隔线 |
| `--px-ink` | `#F6E9C5` | 主要文字和关键数字 |
| `--px-muted` | `#8FAEAE` | 次要文字、冷却标签 |
| `--px-teal` | `#72D2D1` | 己方、护盾、就绪边框 |
| `--px-amber` | `#EDC36B` | XP、时代、可进化、奖励 |
| `--px-enemy` | `#EA8574` | 敌方生命、警告、受击 |
| `--px-heal` | `#8BC6A2` | 治疗、恢复、正向状态 |
| `--px-shadow` | `#02090F` | 实体底边、浮层阴影 |

状态颜色必须同时通过图标形状、边框或文字表达，不能只依赖颜色。生命条的数字和 `aria-label` 继续保留完整值，视觉上只显示必要的短标签。

### 2.3 字体与数字

- `EpochRounded`：中文短标签、按钮、兵卡状态和弹窗正文。
- `EpochDisplay`：营地标题、时代名称、结算标题；只用于大标题，不用于密集资源区。
- `Consolas` 或系统等宽字体：金币、XP、军令、时间、波次、冷却和快捷键。
- 主体中文最小字号 12px；移动横屏的资源辅助标签可以降到 10px，但数字不低于 13px。
- 像素感通过图标、边框、数字间距和短标签获得，不把 Press Start 2P 当中文主字体，以免中文字形缺失和宽度失控。

## 3. 新的 HUD 信息架构

### 3.1 战场三层

```text
┌─────────────────────────────────────────────────────────────────────┐
│ [己方基地]     [金币] [XP] [军令]      [计时/波次]     [敌方基地] [暂停] │  顶部战况带
│ [地图] [前线] [队列] [兵种]                           瞄准提示/战斗浮字 │  辅助与瞬时层
│                                                                     │
│                         净战场与兵线                                  │  Phaser 画布
│                                                                     │
├─────────────────────────────────────────────────────────────────────┤
│ [1][2][3][4][5] 招募队列 │ [战鼓][烟幕][补给] │ [强化][炮塔][时代大招][进化] │ [指挥官] │ 底部指挥甲板
└─────────────────────────────────────────────────────────────────────┘
```

1. **战场层**：由 Phaser 绘制，中心和下半部保持干净，不放永久说明面板。
2. **持久 HUD 层**：顶部战况带、左上辅助按钮和底部指挥甲板，所有内容固定在安全区内。
3. **瞬时反馈层**：瞄准条、伤害浮字、升级提示、错误 toast、暂停/研究/炮塔/进化弹窗；只在需要时出现。

### 3.2 顶部战况带

- 左侧和右侧都使用 `BaseStatusCard`，显示时代图标、基地生命条和短生命数字；点击时只触发镜头定位。
- 中央资源区拆成三个独立 `ResourceChip`：金币、XP、军令。图标占第一视觉层，数字占第二视觉层，文字只用于无障碍和悬停提示。
- 计时器和波次位于资源右侧，使用等宽数字和金色边框；波次结束后只显示“增援结束”短状态。
- 暂停按钮独立为 48px 像素按钮，与敌方基地卡留出 8px 间距。
- 桌面目标高度 72px；短屏目标高度 60px；顶部不能覆盖基地旗帜和建筑主体。

### 3.3 左上辅助控件

默认只显示四个 48px 图标按钮：小地图、跟随前线、训练队列、兵种说明。小地图和移动按钮使用抽屉式展开，隐藏时不占战场空间。

- 图标按钮使用统一的 `PixelIconButton`，不再让地图按钮、前线按钮和弹窗按钮各自定义圆角。
- 展开小地图后，以一个实体像素条显示视野窗口和双方基地色点；不打开大地图页面。
- 队列和兵种说明属于上下文菜单，打开时暂停战斗并获得焦点；关闭后回到原先的战场状态。

### 3.4 底部指挥甲板

底部甲板是方案 1 的主识别元素。桌面高度控制在 136–152px，短屏高度控制在 116–132px；甲板内部使用分段卡槽，而不是三个平等的网页列。

1. **招募卡槽**：五张等宽兵卡，左上角显示快捷键 1–5，中央是像素兵种图，底部是金币数字和锁定/研究状态。特种单位使用金色小徽记，不使用文字星号。
2. **训练队列**：人口和 5 格队列合并为一条窄带；空队列显示五个空槽图标，队列中显示单位图、剩余秒数和进度条。
3. **主动道具槽**：战鼓、烟幕、时序补给固定为三个 60–64px 槽。右上角显示次数，底部显示冷却或短名；冷却使用从底部向上覆盖的像素遮罩。
4. **时代控制**：强化、炮塔、时代大招为三个 56–60px 命令按钮；进化是 72–80px 的金色主按钮，使用环形 XP 进度和下一时代图标。
5. **指挥官槽**：头像、军令数字和生命条集中在一个 68–76px 槽；站位与 Q/W/E 技能在点击头像后展开，不在默认甲板中占满空间。

## 4. 组件和状态规范

### 4.1 组件清单

| 组件 | 默认状态 | 必须支持的状态 |
| --- | --- | --- |
| `PixelFrame` | 深色实体卡 | 普通、悬停、选中、禁用、危险 |
| `PixelIconButton` | 48px 图标按钮 | `pressed`、`disabled`、`focus-visible`、冷却 |
| `BaseStatusCard` | 基地图标 + 生命条 | 正常、受击闪烁、低血量、已摧毁 |
| `ResourceChip` | 图标 + 数字 | 增长跳字、扣除闪烁、资源不足 |
| `RecruitCard` | 单位图 + 金币 | 可招募、锁定、队列已满、按下、特种标记 |
| `QueueStrip` | 空槽或训练进度 | 训练中、出口阻塞、人口阻塞、可取消 |
| `ItemSlot` | 图标 + 次数 | 可用、瞄准中、冷却、次数耗尽、不可选目标 |
| `CommandButton` | 图标 + 短标签 | 可用、禁用、冷却、即将完成 |
| `EvolutionOrb` | 下一时代图标 + XP 环 | 不足、可进化、点击中、弹窗等待选择 |
| `CommanderSlot` | 头像 + 军令 | 在场、驻营、重建、展开军令 |
| `AimPrompt` | 图标 + 短提示 | 技能、道具、时代大招、取消 |
| `PixelModal` | 实体像素弹窗 | 暂停、研究、炮塔、进化、结算 |
| `CombatToast` | 一句短反馈 | 成功、失败、危险、奖励 |

### 4.2 交互状态

- 所有可点击元素保持至少 48×48 CSS px；相邻控件间距至少 8px。键盘和触控都使用同一个 `data-action` 路由。
- 图标按钮必须有 `aria-label`；鼠标悬停可以提供短 `title`，不能把完整规则段落塞进按钮。
- `hover` 只抬高 1px 或变更描边；`active` 使用 1–2px 下压和亮度变化；`disabled` 使用灰度和 48% 透明度，并保留锁定图标。
- `focus-visible` 使用 3px 金色外描边；不通过移除焦点环换取像素外观。
- 冷却不能只显示灰色；需要冷却数字、遮罩方向和冷却图标三种信号。
- 所有“点战场确认”的技能和道具都必须保留右键/Esc 取消、点击按钮再次取消、离开战场取消和多指取消行为。

## 5. 重点流程改造

### 5.1 招募与排队

招募卡点击后立即产生按下反馈，成功训练时在队列条添加对应图标并播放一次短促卡片推进动画；金币不足、人口满和队列已满分别显示不同的红色/灰色状态。队列管理弹窗使用同样的 `QueueStrip` 视觉语言，取消训练后回到原位置，不刷新整个页面。

### 5.2 主动道具与瞄准

道具槽进入瞄准时使用琥珀色外框、中心准星和战场落点预览；`AimPrompt` 只显示“烟幕 · 选择落点”这类短语。成功施放后，按钮先显示消耗，再进入冷却遮罩；战鼓和时序补给的自指向效果直接播放全军脉冲，不强制玩家再点一次战场。

### 5.3 时代升级

进化按钮始终显示下一时代图标和 XP 进度。XP 足够时只做轻微呼吸，不使用持续闪屏。点击后暂停当前战斗，打开三张像素时代卡：时代徽记、一个关键兵种图标、一句短能力说明和确认按钮。确认只调用 `dispatch({type:'evolve', side:0})`，敌方时代不被修改；弹窗关闭后恢复玩家自己的兵卡与资源显示。

UI 验收必须包含以下回归场景：玩家 A2、敌方 A2；玩家进化到 A3 后，顶部同时显示玩家 A3、敌方 A2，敌方兵卡和敌方战场单位仍按敌方时代运行。不能用一个 `uiEra` 或共享徽记替代两侧状态。

### 5.4 研究、炮塔、暂停与结算

研究、炮塔、暂停和结算弹窗共用 `PixelModal`，每个弹窗只突出一个主动作。弹窗顶部显示对应图标和短标题，正文最多两行，复杂说明放入可展开的说明槽。弹窗打开时冻结战斗、锁定镜头拖动并把焦点放在第一可用按钮；关闭后焦点回到触发控件。

## 6. 图标与素材更新

### 6.1 图标图集 v2

当前 4×4 图集只能覆盖高频图标。实现阶段通过用户指定的 Sub2 `gpt-image-2.5` 生成新的像素图标母版，再裁切和归一化为运行时图集。图标必须满足：统一 16-bit 视角、1px 暗色外轮廓、4–6 色限制、透明背景、无文字、无 emoji、24px 和 32px 下都可辨识。

图集 v2 至少覆盖：旗帜、剑、盾、书、遗物、齿轮、地图、暂停、播放、金币、XP、军令、人口、队列、锁定、研究、炮塔、进化、时代五徽记、战鼓、烟幕、时序补给、治疗、护盾、警告、瞄准、返回、确认、取消、左右移动、基地、前线、指挥官。

`src/ui/icons.ts` 改为从一个显式的图标元数据表读取名称、图集坐标、默认色和可访问标签。缺少图集资源时才使用同样方角笔画的 SVG 兜底，不能出现线性圆润图标和像素图标混搭。

### 6.2 资产落点

- 母版与提示词：`output/imagegen/epoch-rush/v0.5-pixel-ui/`
- 运行时图集：`public/assets/ui/epoch-rush-pixel-hud-atlas-v2.png`
- 图集元数据：`src/content/pixel-icon-manifest.json`
- 时代徽记和按钮小图标优先复用图集；单位图、英雄像和基地仍使用现有独立资源。
- 每个新增图集在接入前检查透明边距、像素尺寸、敌我颜色可读性和高 DPI 缩放结果。

## 7. 文件级实施方案

### 第一阶段：令牌与图标基础

1. 新建 `src/ui/pixel-tokens.css`，迁移颜色、间距、圆角、阴影、字体和动效变量。
2. 新建 `src/ui/pixel-components.css`，只放 `PixelFrame`、图标按钮、资源胶囊、兵卡、道具槽和时代按钮。
3. 生成并接入图集 v2，更新 `src/ui/icons.ts` 的显式映射和 SVG 兜底。
4. 保留 `rounded-theme.css` 的旧版本作为回滚参考，但不再继续向其中追加覆盖规则。

### 第二阶段：HUD 模板重构

1. 将 `src/ui/screens-v03.ts` 的 `battleHud()` 拆成 `battleHud()`、`battleTopBar()`、`battleUtilityRail()`、`battleCommandDeck()`、`battleCommanderTray()` 五个模板函数。
2. 更新 `src/ui/screens.ts` 的导出，让新模板成为唯一战斗 HUD 来源；营地、图鉴和构筑页面暂时沿用现有模板，但共享 `PixelFrame` 令牌。
3. 将类名从语义混杂的 `compact-top`、`compact-bottom` 统一为 `battle-topbar`、`battle-utility`、`battle-command-deck`，减少旧 CSS 选择器冲突。
4. `GameApp.paintHud()` 继续负责状态填充，只新增必要的 `data-ui-state` 和 `data-cooldown` 属性；不在模板中复制战斗数值。

### 第三阶段：交互与状态表现

1. 统一按下、选中、锁定、冷却、瞄准、失败和成功的 class 切换。
2. 统一 `aria-pressed`、`aria-disabled`、`aria-live` 和焦点回收；弹窗继续使用现有焦点循环。
3. 为资源变化、基地受击、时代就绪、时代确认和道具施放增加短促的 DOM 反馈，与 Phaser 粒子事件保持同一触发时机。
4. 把升级/研究/炮塔/结算弹窗迁移到 `PixelModal`，保持原有 action 名称和存档行为。

### 第四阶段：响应式与输入

- 1280×720：顶部 72px、底部 144px，五张兵卡完整可见。
- 1024×600：资源标签缩短，指挥官槽收为头像按钮，队列保持一行。
- 844×390：顶部 60px、底部 124px；道具和时代按钮保持 48px，兵卡保留 1–5 快捷键提示。
- 760px 以下：对战仍要求横屏；若竖屏进入，暂停并显示切换横屏提示，不让指挥甲板挤压兵线。
- 粗指针设备：所有按钮至少 48px，间隔至少 8px；安全区使用 `env(safe-area-inset-*)`。
- 减少动态：取消呼吸、位移、屏闪和非关键粒子，保留冷却进度和成功/失败颜色变化。

## 8. 动效与打击反馈对接

视觉更新不重新实现战斗模拟，但要为现有真实事件提供清晰的 UI 反馈入口：

- 招募成功：兵卡短暂向队列方向推进，金币数字一次跳变。
- 资源不足：对应资源胶囊 120ms 红色闪烁，不抖动整个 HUD。
- 基地受击：对应 `BaseStatusCard` 发生 80ms 边框闪烁，战场粒子由 Phaser 播放。
- 单位或炮塔命中：只在屏幕边缘显示轻量伤害浮字，避免中心战场被文字覆盖。
- 时代进化：按钮金色充能 → 弹窗确认 → 450ms 时代切换边框 → 恢复战斗；不持续遮挡兵线。
- 主动道具：按钮发出一次环形像素脉冲，场景内的烟幕、鼓点或补给粒子由 `battle-scene.ts` 继续负责。

每种动效必须有明确触发事件、结束时间和减少动态替代状态；不能给所有按钮都加循环动画。

## 9. 验收计划

### 视觉检查

- 对战首屏能在 2 秒内分辨顶部战况、中心战场、底部指挥甲板。
- 两侧基地的视觉体量明显大于单个单位，生命条和时代徽记不被兵线遮挡。
- 五张招募卡、三枚道具、四个时代命令和指挥官槽均使用像素图标；无 emoji、无风格不一致的圆润 SVG。
- 1280×720、1024×600、844×390 和 760×520 截图中没有横向滚动、裁切关键按钮或遮挡兵线。

### 交互检查

- 鼠标、键盘 1–5/Q/W/E/Z/X/C/R/F/G/V/N 与触控点击执行同一动作。
- 每个图标按钮都有可访问名称、焦点样式和禁用反馈。
- 选择技能/道具后，点击战场、右键、Esc、点击按钮再次取消均有效。
- 训练队列、炮塔、研究、暂停、进化和结算弹窗打开时战斗冻结，关闭后焦点回到触发控件。
- 玩家进化后敌方时代不变化；UI 同时显示双方独立时代，敌方兵卡和单位行为不重建为玩家时代。

### 工程检查

- `npm test` 全部通过，现有时代独立性、队列、主动道具和存档迁移测试保持通过。
- `npm run build` 通过，无 TypeScript 错误、资源 404 或 CSS 未定义变量。
- `prefers-reduced-motion` 和游戏内“降低动态效果”均生效。
- 图标图集加载失败时仍有可识别的 SVG 兜底；图集版本和 SHA 写入素材清单。
- 生产包和浏览器控制台无错误；不启动 Docker、WSL 或任何虚拟化环境。

## 10. 交付顺序

先交付“图标图集 v2 + 令牌文件 + 桌面战斗 HUD”，再交付移动横屏和弹窗迁移，最后处理营地/图鉴/构筑页面的同主题收敛。每个阶段都保留可运行版本和截图，避免把战场操作、时代独立性和存档行为与一次大规模 CSS 改动绑定在一起。

完成后，方案 1 的判断标准不是“颜色变成像素蓝”，而是玩家能在不阅读长文字的情况下，准确完成出兵、排队、使用道具、选择时代、管理炮塔和暂停等核心操作，同时始终看清两座基地和中间兵线。
